# Art Widgets

Интерактивные механики для рассказа об истории искусства. Каждая механика — самостоятельный
Vue-компонент: получает данные через props, ничего не знает о странице и может жить где угодно.

## Структура

```
packages/
  core/        типы, i18n (ru/en), даты, общие composables (usePanZoom, useStepTimer)
  ui/          дизайн-токены (tokens.css), шрифты (fonts.css), иконки, Icon, IconButton, SegmentedProgress
  node-card/   карточка-нода: лицо, оборот, свёрнутый кружок
  story/       сторис-тур по картине с точками и зумом
  time-map/    карта с ползунком времени и периодами
apps/
  playground/  Nuxt-витрина, где механики собраны на одной странице
```

## Команды

```bash
npm install         # один раз, в корне
npm run dev         # витрина на http://localhost:3000 (?lang=ru — русская версия)
npm run typecheck   # типы пакетов и витрины, включая JSON-данные
npm run build       # продакшн-сборка витрины (см. «Ограничения»)
```

## Контракт механики

- **Данные — только через props:** `data` и необязательный `locale`. Схема данных — TypeScript-тип
  в `types.ts` пакета; витрина проверяет JSON по этим типам.
- **Ничего глобального:** никаких слушателей на `window` и поиска по селекторам — только template refs
  и события на своём корне. На странице может быть несколько экземпляров.
- **Внешний вид — через токены:** цвета (чёрное и немного золота), шрифты, радиусы и длительности берутся из
  CSS-переменных `--aw-*` в `packages/ui/src/tokens.css`. Шрифты: Inter Tight — заголовки, Inter — текст,
  JetBrains Mono — подписи и даты, курсив Source Serif 4 — названия картин. Все с кириллицей, `fonts.css`
  подключает их локально.
- **Раскладка — по ширине виджета:** сторис и карта перестраиваются через container queries, то есть
  по собственной ширине, а не по ширине окна. Это важно для встраивания.
- **Тексты:** строки интерфейса — `t('key')` из `useI18n()`, контент — `l(value)`, где `value` —
  строка или `{ ru, en }`.
- **Даты — числа:** отрицательные — до н. э. Строки вида «c. 6500–3800 BCE» / «ок. 6500–3800 до н. э.»
  собираются при выводе (`year`, `yearRange`).

## Историческая карта: данные

Карта охватывает время от 10 000 года до н. э. до сегодняшнего дня. Ползунок нелинейный (`timeScale: "sqrt"`):
последним векам отдано больше места, чем глубокой древности.

Физическая география собирается скриптом и лежит в `apps/playground/public/geo/`:

```bash
npm run geo:build
```

- **Береговые линии эпох.** Рельеф суши и дна NOAA ETOPO1 (шаг 1/6°) «заливается» от океана до уровня моря
  эпохи. Уровни моря взяты по Lambeck et al. 2014 и задаются в `tools/geo/config.mjs`. Впадины, не связанные
  с морем (Мёртвое море, Каттара), сушей и остаются. Мегачад строится так же, по отметке древних берегов.
- **Реки, озёра и нынешний берег** — Natural Earth.
- **Исходники** скачиваются при первом запуске во временную папку системы (`art-widgets-geo`), в проект не
  попадают. Все источники — общественное достояние.

**Государства** — из [Cliopatria](https://github.com/Seshat-Global-History-Databank/cliopatria) v0.2.1
(Seshat Global History Databank, CC BY 4.0): около 1600 государств с 3400 года до н. э. по 2024 год, границы
по 200+ региональным источникам с экспертной проверкой. Слой собирается отдельно:

```bash
npm run geo:polities
```

- Записи типа RELATION (составные империи поверх своих частей) отброшены; «зонтики» с названием в скобках
  (королевство с вассалами, империя с колониями) рисуются пунктирным контуром без заливки.
- Контуры упрощены до 0,1°, координаты хранятся в сотых долях градуса, повторяющиеся кольца — один раз.
  Слой разбит на ~40 файлов по времени (`public/geo/polities/`); карта грузит только нужный.
- Русские названия — по английской статье Википедии через Wikidata/Википедию. Собственные ссылки Cliopatria
  на Wikidata местами ошибочны, поэтому не используются.
- **Проверка дат:** годы каждой записи сверяются с годами основания и распада по Wikidata; расхождения больше
  25 лет попадают в `tools/geo/polity-check.md`. Подтверждённые ошибки имён (например, «Ngô Dynasty» на
  1056–1406 годы — на деле Дайвьет) исправляются списком `CORRECTIONS` в `tools/geo/config.mjs`;
  русские названия для статей-понятий — `RUSSIAN_NAMES` там же.

Вручную в данных карты (`features` в `apps/playground/data/map-ancient.json`) остались только то, чего
нет в Cliopatria: археологические культуры до государств, ледники, бывшие берега, древние русла и названия
исчезнувших земель. Их даты сверены с Википедией (октябрь 2026). У каждой области есть `from` и `to`;
координаты — `[долгота, широта]`. `asTimeMapData()` проверяет данные при загрузке.
Точки с историями видны от `founded` до `until` или до конца последнего периода.

Упрощения: уровень моря одинаков для всей планеты (без поднятия суши после ледников и роста дельт),
Каспий и Балтика — в нынешних уровнях, Чёрное море — на уровне океана. Культуры и ледники нарисованы
приблизительно. Границы Cliopatria — тоже реконструкция: у древних государств они часто неизменны веками
просто потому, что источников мало.

## Новая механика

1. Создать `packages/<имя>/src/index.ts` и `package.json` по образцу соседних пакетов.
2. Добавить алиас в `aliases.ts` (пути в `tsconfig.json` подхватятся сами).
3. Вызвать `provideI18n(() => props.locale)` в корневом компоненте.

## Почему алиасы, а не npm workspaces

Репозиторий лежит на диске exFAT, а exFAT не поддерживает симлинки, на которых держатся
workspaces (npm и pnpm). Поэтому пакеты связаны алиасами путей (`aliases.ts` + `paths` в
`tsconfig.json`), а зависимости ставятся один раз в корне. У каждого пакета всё равно есть свой
`package.json` — он понадобится, когда механики начнут собираться отдельно.

## Ограничения

- **`npm run build` падает на exFAT:** сборщик Nitro ожидает от `readlink` ошибку `EINVAL`, а на
  exFAT Node возвращает `EISDIR`. Dev-сервер работает. Сборка проходит, если проект лежит на NTFS.
- **Ссылки на источники** в `apps/playground/data/portraits.json` — заглушки `example.com`.

## Дальше
